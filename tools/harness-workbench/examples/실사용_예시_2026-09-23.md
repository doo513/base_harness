# 실사용 예시: Windows Harness / AGY 관측 (2026-09-23)

이 예시는 Windows Python 3.14.6 + Tkinter, Bun 1.4.0, AGY 1.2.8 및 `gemini-3.8-flash-high`로 Workbench를 실제 실행한 기록입니다. 계정 토큰, 사용자 식별자와 원본 로그 본문은 포함하지 않았습니다.

## 1. 환경 진단

```powershell
python tools\harness-workbench\workbench.py --diagnose --harness-root . --skip-tls --json
```

관측 결과: Windows, Python 3.14.6, AGY `gemini-3.8-flash-high`, backend boundary `matched`. TLS는 이번 진단에서는 `--skip-tls`로 생략했습니다.

## 2. 화면 및 지속 갱신

- Tkinter GUI를 실제로 열고 닫음: 성공
- GUI 자동 상태 갱신: 2.2초 동안 4회 확인
- `--watch --json`: 5초 동안 JSON snapshot 3개 출력

예시 명령:

```powershell
python tools\harness-workbench\workbench.py --watch --json --harness-root . --log-file .agy-run-harness-monitor.log
```

## 3. 실제 Harness Run 결과

Workbench에서 `--start --follow`로 Windows native Harness와 Windows AGY를 실행했습니다. AGY capability 조회와 모델 stream 요청은 관측됐고, Run 로그는 만들어졌습니다. 다만 Host가 최종적으로 `BadRequest`를 반환해 성공 Run은 아니었습니다.

상태 요약:

```text
source: direct-jsonl
domain: develop
stage: execute
phase: autonomous
model/backend: gemini-3.8-flash-high / antigravity-cli
outcome: BadRequest
active: false
warning: Harness error observed: BadRequest
```

재현 형태:

```powershell
$repo = "$env:USERPROFILE\Downloads\base_harness"
$goal = "$env:TEMP\workbench-smoke-goal.txt"
$log = "$env:TEMP\workbench-smoke.log"
python tools\harness-workbench\workbench.py --start --follow --workspace . --harness-root $repo --goal-file $goal --log-file $log --model gemini-3.8-flash-high
python tools\harness-workbench\workbench.py --status --log-file $log --json
```

여기서 확인된 것은 Workbench가 실제 Run을 띄우고 종료 코드를 기다린 다음 실패 상태를 다시 읽어 보여준다는 점입니다. 이 예시는 Harness 작업 성공 증거가 아닙니다. 실패 원인은 이 Workbench 실행만으로 특정되지 않았습니다.
